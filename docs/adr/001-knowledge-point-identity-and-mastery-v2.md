# ADR-001：知识点实体身份与 mastery-v2 派生模型

- 状态：已接受
- 日期：2026-08-29
- 范围：学习记录、知识点聚合、掌握度计算与数据库演进

## 背景

早期学习链路把 `knowledge_point` 作为自由文本写入作答记录，并把它和学习者一起作为
`mastery_states` 的键。掌握度则使用“历史分数 70% + 本次结果 30%”的累加式 EMA。

这会带来两个问题：同名但属于不同发布版本的知识点可能被错误合并；重复作答同一道已经掌握的题
会持续推高分数。掌握度因此不能可靠地作为老师看板、复习任务或个性化出题的输入。

## 决策

### 1. 知识点使用稳定实体 ID

- `knowledge_points` 保存规范化后的知识点实体。
- 当前实体身份由 `publication_id + normalized_name` 确定，知识点暂按发布版本作用域隔离。
- 客户端只提交题目和作答结果；服务端根据当前学习会话绑定的发布版本解析知识点，客户端不能伪造知识点归属。
- `exercise_attempts` 保存服务端解析出的 `publication_id` 和 `knowledge_point_id`，旧的字符串字段只作为兼容展示值。

当前不提前引入跨教材的 `subject_id` 或知识点类型。等老师视图和真实跨教材使用场景出现后，再基于实际身份
边界决定是否升级为学科/教材/课标作用域，避免先建立一个未经验证的全局知识点体系。

### 2. 掌握度是可重建投影，不是事实记录

- `exercise_attempts` 是不可变学习证据，重复提交仍然保留。
- 对每个 `(publication_id, question_id)` 只取最新一次作答，避免离线重试或重复练习污染聚合结果。
- 正确、部分正确、错误分别映射为 `1.0`、`0.55`、`0.0`。
- `raw_score` 是最新不同题证据的平均值。
- `evidence_confidence` 根据不同题证据数设置上限，当前 1/2/3/4/5 道题对应 `0.6/0.7/0.8/0.9/1.0`。
- `score = raw_score × evidence_confidence`。
- `mastery_states` 只保存当前 projection，并记录 `algorithm_version` 和 `computed_at`，便于重算和版本比较。

领域算法放在 `apps/api/domain/learning/mastery.py` 的纯函数中，持久化层负责取证据和写入，不直接拥有算法口径。

### 3. 数据迁移采用保守、可重复的方式

`scripts/migrate_mastery_v2.py` 提供 `--dry-run`、`--apply` 和 `--verify`：

1. 保留旧的 `mastery_states` 为 `mastery_states_legacy`，不覆盖原始旧投影；
2. 创建知识点实体和 mastery-v2 结构，补齐作答归属；
3. 优先从历史 `exercise_attempts` 重建掌握度，而不是复制旧 EMA；
4. 没有作答证据的旧投影明确标记为 `mastery-v1-legacy`；
5. 迁移在重复执行时保持 no-op，并通过计数和空值检查验证结果。

应用启动时的 SQLAlchemy `create_all()` 只负责初始化缺失表，不负责修改已存在的旧表，因此已有数据库仍必须
显式执行迁移。新建空数据库可以直接由当前 schema 初始化。

### 4. 同一知识点的首次并发写入必须串行化

掌握度行可能在第一次作答时尚不存在。写入前锁定稳定存在的 `knowledge_points` 行，再在事务内重算和 upsert
`mastery_states`，避免两个不同题目的并发作答各自读取不完整证据并覆盖对方结果。该锁只在 PostgreSQL 上承担
生产并发语义；SQLite 仅用于隔离测试兼容。

## 未选择的方案

- **继续依赖自由文本**：实现简单，但无法保证跨版本身份，也无法安全支持老师聚合。
- **继续使用 EMA**：不能从历史事实重建，且重复练习会产生系统性偏高。
- **只复制旧 EMA 到新表**：会把旧的错误口径伪装成新算法结果，因此仅对无证据旧行保留并明确标记 legacy。
- **立即引入全局知识图谱**：当前没有跨教材检索或先修关系的真实需求，过早引入会放大 OCR 和标签错误。
- **把数据库迁移隐藏在 `create_all()`**：无法可靠处理主键、回填和历史数据，失败也难以审计和回滚。

## 后果与后续

- 老师看板、复习任务和个性化出题可以消费稳定的掌握度投影，但当前只保证发布版本内的聚合语义。
- 修改掌握度算法时可以保留作答证据并重建 projection，不需要再次转换事实记录。
- 未来若确定需要跨发布版本聚合，必须先定义知识点的学科/教材身份，再新增映射或迁移，不能直接去掉
  `publication_id` 作用域。
- 当前一次性脚本不是通用迁移框架。进入公网生产前仍需补齐版本化迁移历史、备份恢复演练、低权限账号和 SSL。
