# 学科组试用方案

> 本文只回答“怎样用一次真实试用判断产品形态成立与否”。产品优先级见
> [`product-roadmap.md`](product-roadmap.md)，技术实现顺序见
> [`engineering-roadmap.md`](engineering-roadmap.md)。

## 为什么需要这份文档

[`product-roadmap.md`](product-roadmap.md) 已经把主用户定成“一个学科组的老师”，多轮外部评审
也一致建议“找真实老师验证”。但**验证需要器械**：没有事先写死的失败判据，任何试用都会“成功”
——老师出于礼貌说“挺好的”，然后再也不打开，而我们会把这条反馈记成正面信号继续加功能。

所以本文的核心不是访谈技巧，而是三样必须**在试用开始之前**定稿的东西：

1. 一个压倒性的量化指标及其口径；
2. 一条写死的失败判据；
3. 一份只记录行为、不征求意见的观察清单。

定稿后写上日期提交进仓库。试用中途不得修改判据——改判据等于取消这次试验。

## 前置条件（不满足就不要开始）

试用是一次性资源：一位老师的信任只有一次，第一周崩了就没有第二周。开始前必须完成：

- [x] 掌握度喂回出题（最小版，2026-08-30）：布置作业时能显式说明“本次针对什么 / 避开什么”。
- [x] 教师 override（2026-08-30）：老师可在看板证据行推翻判题或覆盖知识点掌握度，原始证据保留。
- [x] 复核 / 推翻埋点（2026-08-30）：按作业返回复核数、推翻数、复核率和推翻率；推翻结果可作为带标注坏样本来源。
- [x] 版本化迁移（Alembic，2026-08-31）：真实数据进库前已有统一版本链、预检/升级/验证和保留式回填；正式试用前仍需完成备份恢复演练。
- [ ] 一键导入的示例数据包：示例教材 + 示例班级 + 示例作业，老师打开就能看到看板。
- [ ] 移动端错题链路可用：小屏、裁切、弱网恢复。

**明确不需要**：登录鉴权、多租户、权限体系、公网部署。试用在一台机器上跑，
用 `learner_id` 顶着即可（理由见产品路线图“方向 ≠ 部署”）。
2026-09-05 起这句话才真正可执行：学生端此前把身份写死成 `local-demo`，老师加进班级的学生
收不到作业。现在学生端导航上有“我是谁”选择器，从 `GET /api/learners` 读花名册；试用前
老师需要先建班、加学生，学生在自己的设备上选一次自己的名字。**它不是登录**，谁都能选成谁。

## 唯一北极星指标：教师复核率与推翻率

其他指标（完成率、活跃度、生成题数）在这次试用里全部是次要的。理由：一个 AI 判题产品
如果需要老师全量复检，它的净价值是负的——这是外部评审里最尖锐的一条，
而且它是**可测量**的，不必靠感觉。

### 口径

- **复核率** = 老师主动打开查看的 AI 判定数 ÷ 总 AI 判定数。
- **推翻率** = 老师修改了判定结果的数 ÷ 老师复核过的判定数。
- **存疑标记率** = 系统主动标记“需人工复核”的判定数 ÷ 总 AI 判定数。

三个都按“单次作业”聚合，不做学生级归因。

### 目标区间（试用开始前定稿）

| 指标 | 目标 | 含义 |
| --- | ---: | --- |
| 存疑标记率 | < 15% | 系统自己拿不准的比例；过高说明质量门禁太松或题目太难 |
| 推翻率 | < 3% | 老师复核后真的改了的比例；这是判题可信度的直接读数 |
| 复核率 | 第 2 周应显著低于第 1 周 | 信任是否在建立。**绝对值不设目标**——第 1 周高是正常的 |

推翻率超过 10% 就应当中止试用回去修判题，而不是继续收集反馈：
一个会判错的系统收上来的所有意见都是关于判错的。

### 附带收益

老师每一次推翻都带着正确答案，是一条**带标注的真实坏样本**。按既有 Badcase 登记簿流程入集，
这是目前唯一不需要人工采集就能持续扩充金标准集的通道。埋点和 override 入口必须同一批做。

## 失败判据（试用前写死）

> 定稿日期：______（填写后不得修改）

主判据只有一条：

> **第 2 周，在没有我们在场、也没有任何提醒的情况下，这位老师主动布置了第二次作业。**

没有发生就是形态没验证通过，不管他嘴上说得多好。选这条而不是问卷分数的理由：
布置作业是有成本的自愿行为，礼貌性肯定的成本是零。

辅助判据（任一命中即视为该维度失败，需在复盘中单独说明）：

- 老师在试用期内**从未**打开过班级掌握分布看板 → 老师视图的形态错了。
- 推翻率 > 10% → 判题不可信，其余结论全部作废。
- 老师复核完 AI 判定后表示“还不如我自己改” → 二次审核变成了双倍工作。
- 出现一次教材内容错误（题图错绑、公式残缺）被学生看到 → 内容质量门禁不达标。

## 试用前访谈（30 分钟，摸基线）

目的是拿到**可对比的现状数字**，不是介绍产品。产品一句都不要提。

1. 上一次布置作业是什么时候？那次从选题到批完一共花了多久？
2. 批完之后，你怎么知道全班在哪个知识点上错得最多？（观察他是否真的能回答）
3. 上周备课时，找题花了多长时间？题从哪来？
4. 有没有哪次你觉得“这个班的差距太大，一套题没法用”？当时怎么处理的？
5. 现在学校里让你用的系统有几个？你实际每周会打开几个？哪个最烦？
6. 你用过 AI 批改或 AI 出题吗？停用的原因是什么？

记录 1、3 两题的**具体分钟数**，试用结束后同题再问一次。

## 试用中观察清单（只记录，不引导）

坐在旁边看第一次使用，**不解释、不提示、不救场**。老师卡住时先记录卡了多久再开口。

- 从打开首页到完成第一次布置作业，用了多少分钟？中途停顿在哪个界面？
- 第一次表现出困惑的位置是哪里？（记原话）
- 有没有出现“他去点了一个我们没预期他会点的东西”？
- 看板打开后，视线停在哪一块？他先问的第一个问题是什么？
- 他有没有主动去核对某一道题的判定？核对的动机是什么？
- 他第一次说“这个不对”是在哪里？
- 术语：有没有哪个词他要问一遍才懂？（`互动试卷`、`进阶本`、`变式`、`陪练线程` 是已知嫌疑）
- 全程放弃点：如果他中途说“算了我自己弄吧”，记录发生在第几步。

## 试用后访谈（两周后，20 分钟）

不要问“你觉得有用吗”。问行为和取舍：

1. 这两周你打开过几次？最后一次是什么时候，为了什么？
2. （复述基线数字）上次你说批一次作业要 X 分钟，这两周实际是多少？
3. 有没有哪次你看了看板之后，第二天课上真的改了要讲的内容？具体是哪一次？
4. 你推翻过系统的判定吗？哪一道？当时是怎么发现的？
5. 如果下学期只能保留一个功能，其余全部删掉，你留哪个？
6. 你会推荐给同组的另一位老师吗？——如果会，**现在就请他把人叫来**。
   （口头意愿不算数，能不能真的引荐才算。）
7. 什么情况下你会彻底不用它？

## 明确不做

- **不做 NPS、不做李克特量表问卷**。样本量 1～2 人，量表没有统计意义，只会制造虚假的精确度。
- **不做 A/B 对照**。同一位老师同一个班无法做对照组，硬做只会得到一个不可解释的差值。
- **不在试用期加功能**。老师提的每条需求都记录进“已论证但未排期”，试用期内一条都不实现——
  中途改产品会让所有观察数据失去可比性。
- **不做多学科、多年级扩展**。守住初中数学。
- **不承诺后续版本**。试用是验证形态，不是销售。

## 复盘产出

试用结束后必须产出三样，写进仓库而不是留在脑子里：

1. 三个指标的实际数字，与目标区间的对照。
2. 主判据是否命中——一行结论，不许模糊表述。
3. 老师推翻的全部样本入 Badcase 登记簿，标注状态与修复计划。

结论无论正负都要更新 [`product-roadmap.md`](product-roadmap.md) 的执行顺序。
“形态没验证通过”是一个合法且有价值的结论——它比继续加功能便宜得多。
