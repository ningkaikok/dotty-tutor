# 真实质量复核、教学视频与语音交付计划

日期：2026-10-11。基线：`origin/main` 的 `2d440343`；分支：`feature/chapter-quality-media-voice`。
用户授权完成六项任务、以 Luna 极高思考实现代码、由主代理独立验收并发布；用户本人负责真实人工复核。
本计划新增系统内质量复核工作台，避免把临时文件作为持续验收入口。

## 交付范围与完成条件

| 原任务 | 工程交付 | 完成证据与外部条件 |
| --- | --- | --- |
| 1 真实教材验收 | 恢复授权开放教材及来源包；系统内逐案展示原页、定位、许可、版本、预期和实际；持久化人工决定与理由 | 数学 12/英语 6 场景可追溯；用户逐案复核；未复核不得变成已验收 |
| 2 OpenStax 切分 | 支持 `EXAMPLE`、`TRY IT` 及代表练习版式，保持中文试卷与既有题号兼容 | 先复现旧失败，再验证来源页题号、题干与条件；既有切分基线回归 |
| 3 OCR/模型质量 | 有界真实执行及可重复报告；区分 PDF 文字层、扫描 OCR、模型生成、契约重放 | 记录实际 Provider/Model、Prompt/Schema/来源版本、耗时、错误、Token/成本可用性；人工复核语义；不能用替身证明真实质量 |
| 4 人工集/模型横评 | 工作台导入/编写案例，独立标注与复核，匿名 A/B 评分、分歧、正式集导出与统计门禁 | 单审和双审分别展示；只接受满足既有契约的 50+ 人工案例及覆盖；合成与开放来源包不能改名计入人工集；用户单审不能冒充独立双审 |
| 5 视频与语音 | 审核讲解→来源分镜→有界渲染→一致性复核→发布；录音/转写回放→当前步骤追问→打断/恢复/确认 | 先数学知识点与英语段落各一个 60～120 秒视频；片段修订、资源限制、取消和历史不可变；语音先离线再实时；不将观看或未确认转写计为作答/掌握 |
| 6 文档同步 | 修正权限/限流与已完成能力描述；同步代码地图、架构、API、路线图、开发/部署说明和 CHANGELOG | 新模块与接口同批更新三份描述文档；历史报告保留日期，新增本次证据；不将工程通过写成教学效果通过 |

## 系统内质量复核

- 入口属于教师/内容工作台，复用现有导航、原页预览、角色与资源归属、PostgreSQL、Job Store/Worker、API 类型生成及错误协议。
- 案例绑定不可变来源和输出版本。导入带许可、来源类型和指纹；原文件在忽略的数据目录中保留，不进入 Git。
- 列表按教材、模型对比、视频审校及审核状态筛选；详情呈现原页/引用、预期/实际、失败项及必要模型元数据。
- 人工操作明确记录复核者、决定、理由、时间和所审版本；乐观并发防止旧页面覆盖新决定。修改输入或输出必须产生新版本并重审。
- 单审教材验收、双审人工金标准、内容发布批准分别保存状态。复核者不得通过一次操作给自己制造独立双审；工具不自动批准。
- 模型对比先匿名评分再揭盲。覆盖不足、失败臂或尚无评分时不给出正式模型排名；复用现有配对统计与 JSONL validator。
- 支持报告和 JSONL 导出，临时审阅包作为备份/交换格式；原始数据、决定与评测结果持久化恢复。

## 实施批次、依赖与所有权

| 批次 | 责任 | 交付与依赖 |
| --- | --- | --- |
| P0 | 主代理 | 读规则、确认基线、隔离运行数据和测试数据库、形成计划；已有材料只读定位，按许可恢复 |
| P1 | Luna 来源与复核 | 先写业务验收场景；修复切分、实现复核后台/工作台和来源包导入，继而补真实质量执行及横评流程 |
| P2 | Luna 视频 | 独立模块实现来源分镜、版本化产物、渲染与审校；复用后台任务；提供工作台与学生可消费组件；由 P1 统一装配共享入口 |
| P3 | Luna 语音 | 独立模块实现录音/转写确认、当前步骤上下文、取消/代际隔离、恢复及实时交互组件；先离线契约再真实浏览器；由 P1 统一装配 |
| P4 | 主代理 + Luna 修复 | 主代理审查完整 diff、运行独立场景与全部门禁、核对原材料和真实产物；代码修复继续交给 Luna |
| P5 | 用户 | 在工作台完成教材、模型及视频真实复核；独立双审要求另一位真实复核者，不伪造其记录 |
| P6 | 主代理 | 同步文档与版本，提交聚焦 PR、等待必需 CI、合并后确认远端 main，创建正确标签和 GitHub Release |

三位实现者使用 `gpt-6-luna` 与 `xhigh`，共享同一工作区，按文件所有权避免并行覆盖。
P1 拥有共享路由装配、schema registry、主导航及生成 API 文件；P2/P3 提供独立 builder 和集成说明。
P1 新迁移使用 `0017_quality_reviews`；媒体如需新表使用 `0018_lesson_media`；语音如需新表使用 `0019_voice_sessions`，顺序协商并保持唯一 head。
主代理拥有本文、架构/API/路线图和最终验收报告、发布版本及 CHANGELOG，不自行实现产品代码。

## 失败判据与验收

- 来源缺失/篡改、引用不存在、未审材料可发布、学生拿到标准答案或内部审核数据：停止发布，修复并回归。
- 取消后旧响应覆盖新步骤、重复执行写入重复证据、Worker 失租约仍提交、重试预算无界：不通过。
- 任意上传或模型文本被当作可执行代码；任意路径访问、未限制的渲染资源/网络；跨用户数据访问：不通过。
- 真实评测缺来源/版本，文字层被标为 OCR，成本不可用却填写估计账单，合成数据计入人工集：不通过。
- 视频旁白/字幕/公式/条件/原文定位不一致，或用无旁白幻灯片宣称完整视频：保持待审，不发布该内容。
- 不支持的录音/浏览器/转写提供可理解的回退与手动确认；不得用静态文本替身宣称真实实时语音已验收。

后端实际运行：`uv run ruff check .`、`uv run pyright`、`uv run python -m unittest discover -s tests -p 'test_*.py'`，使用专用 PostgreSQL admin 创建一次性数据库，不共享应用库。
前端实际运行：`pnpm lint`、`pnpm vitest run`、`pnpm check:api`、`pnpm exec tsc --noEmit`、`pnpm run build`、独立端口 `pnpm run test:e2e`。
另运行测试纪律、确定性 replay、章节基线、真实来源重放及新增真实产物检查；配置/Docker 变化追加 compose config/build/up/health/down。
验收报告分别记录本机与远端 CI、通过/跳过/失败、真实/合成、工程/人工/教学效果证据，不混用。

## 发布边界

预计功能版本 `0.35.0`，创建前确认远端版本未被占用。用户已授权提交、推送、合并和发布，采用受保护 PR 流程。
版本发布必须有本机验收、必需 CI、合并 main、标签指向合并版本及 GitHub Release；生产部署单独取证，不由发布标签推定上线。
若人工材料/第二位复核者尚未提供，继续完成全部工程与可复核内容；报告并保留实际待审状态，不能宣称六项真实质量条件全部完成。
待审内容不得绕过现有发布批准。公开版本只能按实际通过的工程范围描述功能与限制。
