# 无感制作与连续学习开发计划

日期：2026-10-23。基线：main `8818217e`。本轮由 Luna（极高推理）实现，主代理独立审查与验收。

## 交付目标

老师一次设定制作/学习范围；学生从统一入口继续学习，系统衔接订正、巩固和到期复习。
文件在 API/Worker 重启、本地缓存丢失后仍可恢复。整本教材按小批次持续制作，不要求重复选页。
沿用既有判题、掌握策略、租约队列、来源检查与发布门禁，自动化操作留真实系统身份记录。

## 第一阶段：文件持久化基础

- 保留现有本机目录和 URL，增加可选远端私有存储，优先复用已用 Supabase 与现有 HTTP 依赖。
- 覆盖教材原件、OCR/题图及课件引用素材的真实写入和读取链路；不只新增一个无人调用的适配器。
- 远端成功且指纹核验后才报告持久化完成；失败可重试，缓存缺失按受控记录恢复，文件损坏明确报错。
- 远端对象不得公开绕过现有访问控制；服务端凭据不得进入前端、日志或数据库业务响应。
- 大文件不能默默降低现有上传上限。Supabase 免费项目单对象上限 50 MB，采用有界分片等兼容方式；不自动购买套餐。
- 原有本机文件通过显式、可重复的迁移/补存命令接入，提供只读检查和真实迁移统计；不删除原件。

验收：独立缓存 A 写入并持久化；缓存 B/新进程从远端恢复原 PDF 与图片且哈希一致；失败不假报成功；路径穿越、外部路径、未授权素材访问被拒绝。本机未配置远端时行为兼容。

参考：[官方文件限制](https://supabase.com/docs/guides/storage/uploads/file-limits)、[Storage REST API](https://supabase.github.io/storage/)。

## 第二阶段：统一学习入口与自动衔接

- `/learn` 主入口提供“开始/继续学习”，按可解释的固定规则选出下一项，并保留自主选择和退出能力。
- 复用真实作业进度、错题阶段、验证证据与复习到期时间；服务端事实决定完成状态，不能仅靠点击、本地计时或模型口头判断。
- 从一个连续流程完成作答、订正、巩固和复习，减少返回列表和逐项点击“生成/开始下一道”的动作。
- 保留提示、订正思考和错误原因的有效教学环节；高置信的已有题目不重复人工确认，拍照歧义不能冒充已核验。
- 正确反馈保留阅读窗口和手动停留；未达掌握门槛时自动补练最多连续准备四题，之后在原页提供“再练一道”，每次明确操作只准备一题；达到既有掌握门槛后衔接下一项，到期复习自动准备，避免无限生成和重复模型调用。
- 页面刷新、重复点击、断网及恢复、身份切换后恢复正确位置；提交幂等，不重复记错、排复习或串学生。
- 只在学生明确开始学习后触发必要生成；单纯访问首页/GET 不触发昂贵模型调用。

验收场景先于实现编写：有作业和到期复习时开始学习；答错自动记录并衔接订正；掌握后自动继续；未掌握不跳过门槛；刷新/离线恢复/切身份/重复提交；无任务及部分接口故障不误报完成。

## 第三阶段：整本教材自动续做

- 明确选择整本自动制作后，复用原件页数和已有目录，按有界页段建立并持续推进批次；可先使用已完成课时。
- 最多覆盖 1000 个原 PDF 物理页，每批最多 30 页，最多 `ceil(1000 / 30) = 34` 批；773 页教材对应 26 批。每批最多生成 45 张课件页。
- 用持久进度和现有 Worker 租约衔接来源准备、规划、生成、检查/修复、发布与下一批。
- 同一来源指纹与批次幂等；重启/重试不漏页、不重复发布、不覆盖已发布和人工修改的课件。
- 保留试卷生产路径；不把试卷误当教材，不擅自扩大明确选择的局部范围。
- 暂时性网络故障等待恢复；持续内容冲突明确列为异常。并发、尝试次数和模型消耗有界，可暂停/继续，进度区分制作中、等待、异常和完成。

验收：超过 30 页的教材无需重新选页即可完成多个批次；中途重启恢复；单批失败不重做成功批次；两个 Worker/重复请求不重复；手改和历史发布保持；来源变化停止旧任务；试卷与局部模式兼容。
