最近验收快照中三个单元未生成原页分别为 27/13/19；执行前重新读取覆盖，不硬编码历史缺口。

## 执行分工

沿用用户已授权的子代理实现、主代理独立验收方式：

- courseware_assets：完整单元补齐建议后端与持久化边界回归；不改前端和评测模块。
- frontend_system：补齐建议的页面、Hook、组件和用户流程；复用已有按钮/表单/提示。
- quality_workflow：人工评测准备诊断、失败场景与命令文档；不改课件资产或共享前端。
- 主代理：计划与路线图、公开 science 来源准备、运行盘点、接口文档同步、集成和独立验收。

## 技术实验执行顺序

1. 教材原文片段检索：PostgreSQL FTS 为基线，证据必须绑定来源版本和页码；撤回来源不可继续引用。
2. 互动数学：函数/滑块或拖拽几何只选一项，复用答案契约，实验不写掌握度。
3. 媒体表现与音频缓存：同一已审核教学描述对照现有 renderer 与候选方案；缓存键包含文本、语言、声音和 renderer 版本。
4. WebLLM/Prefix Cache：先独立提示或 warm/cold/control 探针，报告有效命中与实际收益；未验证时不启用生产。
5. 知识点树：只从可追溯教材目录派生，保留版本和人工确认；不让模型猜先修关系并写入学习状态。
6. 模型路由、视觉复审、工具安全和长期上下文：复用现有评测与 shadow 基础；正式质量结论受批次 3 门槛约束。

这些方向是按依赖推进的实验队列，不把“已写实验计划”记作功能已完成。

## 验证与交付

先写可观察的失败与用户场景，再实现。新增接口同步 codebase-guide、architecture 和 api，生成类型由脚本更新。
执行 AGENTS 所列后端 Ruff/Pyright/unittest 与前端 lint/Vitest/API 类型/tsc/build；触及用户流程时执行 Playwright。
后端持久化测试仅连接显式隔离 PostgreSQL，不接原本机库或线上库。
运行切换须单独记录备份、还原验证、迁移和服务健康，不因 Git 同步即宣称上线。
真实模型/OCR/TTS 运行须记录范围和结果，不将 fixture 或合成评测冒充真实材料质量。
结果记录在 `docs/roadmap-development-acceptance.md`；缺少扫描或真人审核时完成不依赖这些输入的工作，再列出具体阻塞项。
