# 已有功能完善与新增功能开发计划

更新日期：2026-10-15。代码基线为 v0.39.0 / main `985b4e5`。
已按用户要求启动三线并行开发，当前实现与实际验证见[本轮验收记录](development-parallel-acceptance.md)。历史结果见[2026-10-13 验收记录](roadmap-development-acceptance.md)，不沿用旧测试结果作为本轮通过依据。

## 本轮目标与已完成基础

先让已有教材制作与复核流程更容易恢复、定位问题，再补齐单元授课、学生续学和来源检索。
产品范围与最终验收仍以[产品任务 PP1–PP7](product-roadmap.md#产品任务与用户验收)为准；本页安排开发包、实施顺序与并行边界，
不将此前讨论的可靠性评测方向自动升级为项目转型。

以下能力已经实现，后续直接复用：自动识别/规划/生成与最终预览确认、按批次增量补齐、AI 初审与抽检统计、
公式发布保护、播放器与按学习者/发布版本隔离的本机恢复、通用 OpenAI 兼容接口、模型指标及评测/盲评基础。
本轮补充教材原文片段检索、按章节组织的单元目录和服务端续学位置；下文保留开发包的目标与验收标准，完成范围以本轮验收记录为准。

已记录缺口直接开发；已经覆盖的恢复、幂等和权限行为先回归，出现可复现问题才修复，避免重写现有机制。
工程测试、真实模型运行、教师内容审核、正式双审评测分别报告，不互相替代。

## 计划 A：完善已有功能

### A1：制作失败后知道下一步做什么（首轮，优先）

- 交付：在来源准备、规划、生成、复核和发布处显示当前状态与下一步操作；失败能定位原页/课时并进入现有重试、修订或预览入口。
- 范围：制作页面、工作流 Hook 和现有任务状态；不另建任务中心。刷新恢复、取消和发布响应丢失已有回归，不重新实现。
- 验收：`user Given 来源识别失败 When 返回教材 Then 能看见失败原页并进入重试入口`；刷新后恢复原任务，不重复生成。
- 并行边界：先做前端状态与提示；确需新增响应字段，由集成负责人统一修改契约。

### A2：完整单元补齐保留已完成工作（第二轮，优先）

- 交付：在已有增量补齐上完成至少两个批次的端到端验证，核对教师修改、旧发布、覆盖缺口和局部失败恢复；只修复实际暴露的问题。
- 范围：`courseware.py`、`courseware_completion.py`、批次归属规则、覆盖面板和已有 PostgreSQL 测试。
- 验收：`user Given 第一批已编辑且发布 When 补齐第二批并重试失败页 Then 原编辑和旧发布保持可读且已完成页不重做`；来源变化或旧 Worker 迟到时拒绝过期写入。
- 工程先用固定场景验证，再制作一个英语、一个数学完整单元交教师核对。历史 27/13/19 页缺口仅为旧快照，执行前重新读取。

### A3：AI 初审结果可以校准（第二轮后）

- 交付：用固定版本材料核对原文、公式、图文和答案问题，复用现有问题页/抽检页及一致率统计，说明已复核数量和统计口径。
- 验收：`user Given 初审后页面被修改 When 再次查看 Then 旧结论不能作为当前版本的审核依据`；未逐页核对的批量确认页面不计为独立正确标注。
- 问题页与抽检页存在选择偏差，当前样本一致率不能直接称为全量漏报率；需要总体估计时，另设随机独立核对样本。
- 开发样例验证统计，真实材料由人独立复核；无人复核时交付工具和待审清单，质量结论保持待验证，不新增审批系统。

### A4：OCR 错误可复现并定向修复（第二轮后）

- 交付：分别固定数字 PDF、纸质扫描、公式和图文混排样例，记录原图、OCR 输出和可定位差异，再按失败类型修复现有路由或规范化。
- 验收：`user Given 公式识别损坏 When 生成或发布 Then 保留原始 OCR、展示原页并要求修订`；新增拦截规则不代表识别准确率提高。
- 依赖：A6 可支持原图/转写对照；真实扫描缺材料时先完成本地样例和报告结构，不能宣称扫描质量已通过。
- 复用 OCRRuntime、来源版本和坏样本机制，取得实际失败证据前不更换 OCR 基础设施。

### A5：手机播放、视频与语音核验（后续）

- 交付：核验手机切页、作答、刷新、身份切换和弱网恢复，以及来源撤回后的图片/视频/语音访问；有可复现缺陷再修复。
- 验收：`user Given 同一设备切换学习者 When 打开同一课件 Then 不恢复另一人的输入`；来源撤回后旧媒体不能继续展示不可用内容。
- 浏览器固定场景可先完成；实际手机、真实扫描、真人听评分开登记设备与结果。无对照数据时不扩建动画、实时语音或缓存系统。

### A6：评测真正传入图像（首轮，可独立）

- 交付：为现有图像候选补齐实际输入与素材指纹，记录实际输入类型、成功/失败、延迟和用量；同题原图、正确转写、损坏转写分组比较。
- 范围：`tutor_model_evaluation.py`、素材校验、已有 Runtime 和报告；通用 OpenAI 兼容接口已经完成，不重复开发。
  SVG 若不被目标模型支持，复用已有渲染器派生 PNG 并保留素材指纹关系。
- 验收：`user Given 有效图像案例 When 运行对照 Then 实际传入图像而非仅把路径写进文本`；无视觉能力、缺素材、超时及未知用量分别报告。
- 先完成离线/外部 Runtime 替身验证，再做有界真实实验；不把失败样本静默排除，不把未知费用记作零。同题变体按题目分组，不能充作独立样本。
- 正式结论沿用独立人工金标准和盲评门槛，50 条合成候选不改身份计成人工案例。

## 计划 B：开发尚未完成的功能

### B1：单元目录与跨课时授课（首轮，PP3）

- 交付：基于已有教材/章节与保留批次组织目录，展示课时顺序、来源范围、可用发布；能返回目录和切换课时。教师可见草稿状态，学生只见可访问发布。
- 先明确单元与现有章节的对应、跨批次排序、每课时 publicationId。优先复用现有身份，只有模型不足时才增加最小持久化契约。
- 验收：`user Given 单元有已发布和待审课时 When 学生打开目录 Then 只看到可访问课时且不泄露答案`；旧版本链接可解释，撤回课时有不可用提示。
- 增量批次能力已存在，不等待重做 PP1。目录契约先稳定；A2 若改变批次归属，先完成兼容设计，再集成相关核心代码。

### B2：学生跨课时继续学习（B1 契约稳定后，PP4）

- 交付：已有学生任务入口显示继续学习，区分上次打开、活动已作答和待订正，恢复指定单元、课时与发布版本；核对并补齐课件作答和错题/复习证据衔接。
- 本机页码恢复已有，本项新增服务端单元进度和跨课时衔接。复用现有学习者归属，不扩展账号或多租户。
- 验收：`user Given 学生在第二课时作答后离开 When 再进入 Then 恢复本人原发布版本且作答不重复计数`；观看末页不增加掌握度，失效发布不套用旧作答，弱网重试幂等。
- 可基于 B1 固定契约先开发组件，服务端联调等待单元/课时/发布身份稳定。

### B3：查教材原文并回到证据页（可独立，PP5）

- 交付分两步：先检索已审核教材片段并回跳原页，再让讲解携带可核对引用；证据不足时提示补充材料。
- 复用 PostgreSQL FTS、来源定位与预览，补教材片段和来源/发布版本绑定，兼容原题目索引；不预设新增 embedding、reranker 或向量库。
- 验收：`user Given 两版本教材有相似片段 When 在当前课时提问 Then 引用来自可访问的当前来源`；撤回、修订或权限失效时，即使索引未清理也不能继续返回旧正文/原图；无证据不编引用。
- 依赖已有来源/发布契约，独立检索入口无需等待 B1/B2，接单元导航时再联调。先固定有依据、无依据和冲突案例，用 A6 报告能力对照；命中率不等于讲解正确率。

### B4：一个可操作的数学示例（B1/B2 稳定后，PP5）

- 交付：函数参数探索或拖拽几何只选一个场景，嵌入现有播放器，支持触控、键盘、恢复和静态回退。
- 先检查现有点放置画布与答案契约，不足时再按维护状态、许可、包体积和环境比较一个成熟库。
- 验收：`user Given 可操作示例 When 改参数并提交 Then 输入按已有答案契约判定`；交互失败可看静态内容，拖动或观看本身不写掌握度。
- 与 B2 共同修改播放器或内容块契约的部分串行集成。

### B5：一节科学课的实际成品（质量工具就绪后，PP6）

- 交付：使用已有 science profile 和候选来源，先校对粘连文字，再制作一节有图表、活动和来源的待审课件。
- 验收：来源/许可可核验，实际模型运行有记录，内容由有相应能力的人逐项核对；未经审核的候选不算教学成品，不合并英数科学掌握度。
- 依赖 A3/A4 的质量反馈与可用材料，可先准备素材，真实生成和审核排在首两轮之后。

### B6：把已发布内容带走（后续，PP7）

- 顺序：先利用已有渲染链路提供可打印且保留来源署名的 PDF，再按需求补可编辑 Word；开始前检查已有依赖与成熟实现，不自写公式或分页引擎。
- 验收：`user Given 已发布课件 When 导出学生版 Then 图文、公式、页码与署名完整且没有教师答案`；教师答案版单独选择，导出固定版本，素材遵守现有分发范围。
- 依赖发布投影和 B1 的课时顺序；真人试用可先准备观察场景，正式使用仍需参与者与已审内容。

## 可以同时开发什么

本轮使用三个并行执行者，按以下模块分工；共享契约、迁移、应用装配与最终验证由集成负责人统一处理，改动保留在现有工作区。

1. **教材制作线**：A1 → A2 → A3/A4 → A5，先把制作流程用顺，再按实际质量问题修复。
2. **单元学习线**：B1 → B2 → B4/B6，先目录与续学，互动和导出逐项增加。
3. **AI 与证据线**：A6 → B3 → 支持 A3/A4 与 B5，先修好评测输入，再做教材证据检索。

箭头表示该线推荐顺序，不要求不同线等待全部真人内容验收。

### 第一轮：流程提示、单元目录、图像评测

- 并行 A1、B1、A6，B1 在目录/发布契约确定后实现；A1 改制作页面与 Hook，B1 改目录查询与导航，A6 改评测输入和报告。
- `courseware.py`、`model_runtime.py`、共享契约、依赖锁、迁移及生成 API 类型由一个集成负责人修改；其他开发包提交需求，避免同文件并行写入。
- 交付：失败后有下一步操作、能切换已发布课时的目录、实际接收图像的评测链路。固定数据先验工程，真实质量单列。

### 第二轮：完整单元回归、跨课时续学、证据检索

- 并行 A2、B2、B3；B2 依赖第一轮目录契约，B3 先独立检索再接导航。
- A2 若改变课时身份或发布契约，先完成兼容变更再继续 B2 联调；迁移编号和 schema 统一顺序分配。
- 每个包用独立测试数据库与端口。若实施采用多执行者，须隔离修改范围或用独立工作区，不能多人同时写同一文件。
- 交付：多批次保留教师工作、学生恢复单元学习、引用回原页且撤回后不可继续读取。

### 第三轮：真实质量核对与后续体验

- 用版本固定的材料开展 A3/A4，按失败证据修复；A5 的设备核验可同步进行。
- B4、B5、B6 每次最多新增一个开发包，首两轮完成后再按实际问题和维护负担排序。
- 动画、TTS 缓存、本地提示推理、知识点树保留在实验候选池；多租户、商业化和高可用沿用暂缓范围，不占首两轮交付。

## 测试与完成标准

先写 `user` 开头的 Given/When/Then 验收场景，已有场景直接复用；纯规则用单测，组件用 Vitest/RTL，跨课时路由与布局用 Playwright。
模型/OCR/TTS 仅在外部边界替身，真实实验记录范围、模型、调用次数、用量和费用口径。

- 开发中执行 `python scripts/test-changed.py --base HEAD` 及相关 lint/类型检查。
- 交付按 [AGENTS.md](../AGENTS.md#验证与交付) 执行后端 Ruff/Pyright、前端 lint、API 漂移、tsc、build 及相关测试；用户流程/DOM 变化执行 E2E。
  允许交给 PR CI 的全量项目明确列出，CI 未出结果不报通过。
- 存储、迁移、共享契约、测试设施或依赖变化，本地跑显式隔离 PostgreSQL 的后端全量；缺环境明确列未验项，不使用业务库替代测试库。
- 新模块、端点或响应字段同批同步 architecture、codebase-guide、api，生成类型由脚本统一产生。
- 每包记录实现、实际执行命令、失败修复及人工待办，不预填通过结果；工程与真人内容验收分开记录。

首两轮分别是可演示交付点，不承诺未经执行验证的日历工期。
真实教师审核、扫描、听评、50+ 独立双审与正式盲评是内容验收依赖，不阻塞固定场景可验证的工程开发；
材料/参与者不足时保留“工程完成、内容待验”，不削弱入集与发布门槛。部署独立交付，Git 同步不等于上线。
