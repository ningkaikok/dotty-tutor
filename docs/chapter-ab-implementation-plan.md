# 数学章节与英语阅读实施及验收计划

本计划按 2026-10-02 路线图展开。2026-10-03 用户确认本次连续推进 A/B（批次 1～4），由 Luna 实现、主代理独立验收；批次 5～6 只保留规划。用户随后明确要求完成后推送合并；通过独立验收后创建 PR，等待 CI 门禁通过再合并，不包含新版本发布。

## 目标与证据边界

交付一个数学章节和一篇英语课文的来源关联课程闭环：导入已有 OCR 产物、定位来源、生成有限课程模板、复核、发布、学生作答、刷新恢复。既有题目、作业、错题、掌握度和复习保持兼容。

当前未提供授权教材与真实人工复核记录。先用明确标注的原创合成场景建立工具和可运行演示，人工复核状态保持待复核。合成测试通过只能证明工程行为，不表示完成真实教材验收、50+ 人工金标准或学习效果验证。人工审核标记只由用户明确操作产生，不由模型自动批准。

## 顺序、交付物与失败判据

| 批次 | 交付物 | 依赖及独立验收 |
| --- | --- | --- |
| 1 场景与基线 | 一个初中数学章节的 10～20 个合成候选；独立英语阅读场景；来源许可、版本、页码/区域、预期输出、复核状态；验证和基线 CLI | 覆盖文本/扫描 OCR 产物、公式、图表、缺页、错图、漏条件；拒绝重复 ID、缺元数据和伪造人工批准；报告失败项，OCR/模型调用未执行必须明确标记 |
| 2 来源与修订 | 章节来源契约、来源指纹、页码/区域回看、修订依赖及不可变发布历史 | 缺失来源不能发布；来源变更使受影响草稿重新待复核；发布版本及旧作答不被覆盖；原文字符 offset 不作为唯一位置依据 |
| 3 数学章节闭环 | 概念→例题→提示→检查题有限模板，工作台审阅发布及学生消费入口 | 复用上传/OCR、课程块/播放器、确定性数学判题；刷新与重试可恢复，重复 attemptId 不产生重复学习证据；学生不能消费草稿或取得标准答案；观看不更新掌握度 |
| 4 英语证据判定 | 原文段落/句子定位、词义/指代/明示/推断题、答案与依据分别保存、独立学科判定 | 答案对但依据错不能判正确；合理改写不能靠字符串精确匹配误判；未校准简答保持 needs_review 并支持人工复核；数学原流程回归；不合并跨学科掌握度 |
| 5 视频（后续） | 审核讲解→分镜→渲染→一致性审校，60～120 秒单知识点内容 | A/B 验收后启动；比较现有 Canvas/SVG 与一个候选；公式、条件、字幕、旁白、原文标注一致；片段修复、资源/费用/重试限制；观看不写掌握度 |
| 6 语音（后续） | 离线录音/转写回放，再接入当前步骤实时追问 | 教学步骤稳定后启动；定位、打断、旧响应取消、重连、歧义确认；转写经确认才进入作答证据，不加入未校准的发音评分 |

## 实现约束

- 后端遵循路由/协议→领域编排→Runtime/Store；应用装配文件不承载业务。持久化沿用 PostgreSQL 和版本化迁移，不使用进程内字典充当可恢复存储。
- 有耗时模型调用时复用 Job Store/Worker、快照和有限重试；确定性模板明确标明生成方式，不把模板演示写成 AI 质量结论。
- 前端复用 LessonPlayer、rendererRegistry、MathText 和现有作答组件；页面组合，网络与状态进入 Hook；不让任意生成 HTML/JS 进入执行路径。
- 来源更新通过新修订表达；发布快照保留其来源版本。英语目标、策略与证据显式带学科作用域，不沿用数学定量掌握门槛。
- 每个边界先写 `user` 开头 Given/When/Then 验收场景，再实现。测试断言可观察结果和持久化，不断言内部调用次数。

## Luna 分工与集成

1. 场景实现者只负责 `apps/api/evaluation/chapter/` 与基线测试，保持合成身份和复核入口。
2. 后端实现者负责契约、领域服务、Store/迁移、路由和行为测试；先给前端稳定接口，再实现持久化闭环。
3. 前端实现者负责工作台、学生页面、Hook、类型生成、组件测试及跨页 E2E；直接与后端对齐契约。
4. 主代理维护计划、架构/API/代码地图/变更说明，审查差异，独立执行验证，发现问题退回修复并复验。

## 独立验收与交付

验收核对每批次失败判据，重点检查缺来源发布、修订历史、学生答案泄露、英语证据归属与简答不确定性、attempt 幂等和刷新恢复。迁移及 Store 用专用临时 PostgreSQL 实例验证，不访问应用库或学生数据。

实际执行 AGENTS.md 全套后端命令（ruff、pyright、unittest）和前端命令（lint、vitest、check:api、tsc、build）；用户流程/DOM 改动执行 E2E。执行测试纪律检查。Docker 文件发生变化时才追加 Docker 验证。记录通过、失败、跳过数量与环境限制，不把跳过的数据库测试算通过。

新增模块同步 codebase-guide.md、architecture.md；新增接口同步 api.md，API 类型通过 generate:api 生成。路线图区分实现完成、合成演示验收、真实教材人工复核与教学效果验证。最终交付可运行入口、可复现命令、失败报告、技术决策和仍未验证边界。

## 批次 1 首轮验收记录（2026-10-03）

主代理独立执行以下命令，通过 10 个基线行为测试、17 个英语判定行为测试和场景检查：

```bash
cd apps/api
uv run python -m unittest tests.test_chapter_baseline tests.test_chapter_english_evaluation -v
uv run python -m evaluation.chapter.baseline --check --json --output /tmp/chapter-baseline-report.json
```

包含 12 个数学候选与 6 个英语候选。数学生产来源切分基线保留 4 个已知失败场景（缺页、错图、漏条件、公式截断）；英语 6 个仅为 fixture 自检，其中 1 个预期拒绝错误依据，不计作产品已知缺陷。所有候选仍为 `synthetic / pending_human_review / counted=false`。成本字段为 `null`，未运行 OCR、模型或学习效果实验。已知失败签名改变时要求重新核对基线，CLI 通过不等于这些缺陷已修复。

候选来源、逐项复核与局限见 [场景说明](../apps/api/evaluation/chapter/README.md)。批次 2～4 的最终门禁与修复证据见 [验收记录](chapter-ab-acceptance-report.md)。
