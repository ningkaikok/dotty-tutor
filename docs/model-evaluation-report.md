## 2. 测试目标

本轮测试验证以下能力：

1. 大 PDF 是否可以分块上传、按页处理并持久化。
2. MinerU 是否能输出包含题干、公式和题图的 Markdown。
3. 第一模型是否能生成结构化题目、四步讲解和引导卡。
4. 第二文本模型是否能复核 OCR、公式和第一遍结构化结果。
5. 视觉模型是否读取真实图片、判断图片归属，并检查图片、题干与讲解的一致性。
6. 不确定或存在冲突的结果是否被标记为人工复核，而不是错误地进入“审核通过”状态。
7. 后端自动化测试、前端类型检查与生产构建是否通过。

## 4. 当前处理链路

```text
PDF 分块上传
  → 合并、文件完整性校验、按页规划批次
  → MinerU OCR，持久化 Markdown 和题图
  → 第一模型生成结构化题目与四步讲解
  → 第二文本模型复核 OCR、公式、条件和讲解
  → 确定性公式规范化检查模型残留的控制字符和错误 LaTeX
  → 视觉模型读取实际题图，判断归属并检查内容冲突
  → 结果及完整 review 记录写入 PostgreSQL JSONB
  → reviewed 或 needs_review
```

## 7. 真实教材链路测试

### 7.1 测试输入

- 教材：`2018北京市中考数学试题(含答案解析版).pdf`
- 持久化上传 ID：`dc8a7fca15a24d54ae1f2e54796fd7a8`
- 样例批次：`batch-002`
- 样例题：第 21 题，包含几何图形、平行关系、垂直关系和根式。

### 7.2 持久化模型运行记录

| 阶段 | 实际运行模型 | 结果 |
|---|---|---|
| 题目生成 | Ollama `qwen2.5:3b` | 成功生成结构化结果 |
| 文字复核 | Ollama `qwen2.5:7b` | 执行成功，但输出仍残留错误转义 |
| 公式合并保护 | 确定性规范化规则 | 成功识别并替换异常模型输出 |
| 图片审校 | Codex `default` | 成功读取图片并判断属于当前题 |
| 最终门禁 | 双模型审校状态 | `needs_review` |

### 7.3 OCR 与公式修正结果

最终持久化题干包含：

```text
AB ∥ DC
AB = AD
CE ⟂ AB
AB = √5
BD = 2
```

本轮发现第二文本模型曾把 LaTeX 的反斜杠错误地输出为 JSON 控制字符，例如把 `\parallel`、`\bot` 和 `\root` 的开头解析成换行、退格或换页。系统没有直接采纳该结果，而是检测异常后回退到同一 MinerU 原题块的确定性规范化结果，并把修改原因写入 `review.text.corrections`。

结论：**公式保护机制有效，但第二模型单独处理公式的可靠性仍不足，不能移除确定性校验层。**

另一个真实回归样例中，第一模型给出的温度公式是可渲染的，第二文本审校却把百分号和摄氏度改写为
`\textbackslash\text{%}` 与 `\textdegree C`。这说明模型能力较强并不等于整条多模型流水线必然正确：
后处理必须统一修复已知命令，并由质量门禁拒绝“百分比题干 + 全部温度选项”等单位冲突。

### 7.4 图片理解与关联结果

视觉模型将题图判定为属于第 21 题，并识别出：

- A、B、E 位于同一直线，B 位于 A 与 E 之间。
- D、C 位于上方，DC 近似水平。
- 对角线 AC、BD 交于 O。
- 图中连接了 OE。
- CE 与 AB 所在直线垂直，E 处存在直角标记。

视觉模型同时正确指出，图片没有平行线、等长和角平分线的明确符号，因此不能仅凭图形外观证明 `AB ∥ DC`、`AB = AD` 或 AC 为角平分线。这些关系必须来自题干。

结论：**视觉模型确实读取了图片内容，而不是只根据题干猜测图片归属。**

### 7.5 讲解一致性检查结果

视觉审校发现并拦截了以下问题：

1. 第一讲解步骤中的角名称与角平分线条件不一致。
2. 将“AC 平分某角”的题设错误归因于“对角线交于 O”。
3. 从 `AB ∥ DC` 推导出的角关系不成立。
4. 第三步声称计算 BD，但 BD 已经是题目给出的已知量，实际待求量为 OE。
5. 结构化 `givens` 遗漏了第二问中的 `AB = √5`。

系统最终将该题标记为 `needs_review`，没有误标为审核通过。

结论：**审校门禁达到了“发现问题并阻止错误内容直接上线”的目标；讲解自动修复能力仍需继续加强。**

### 7.6 项目迁移后的图片资产回归

项目移动到独立目录后，首次打开历史教材时图片全部显示破损图标。排查发现旧 SQLite 的 `upload_jobs.directory` 仍保存迁移前的绝对路径，资产接口因此返回 404；磁盘上的 JPG 文件本身没有丢失。

已完成修复：

- 将教材的持久化目录更新为当前项目的 `data/uploads/...`。
- `TutorStore` 增加旧项目路径自动解析逻辑，后续迁移不会直接失效。
- 补充“项目移动后数据库目录兼容”回归测试。
- 浏览器实际打开历史教材并滚动到题目区域，四张图片正常渲染。
- 题图关联改为以 MinerU Markdown 的原始引用顺序为准，不再采用模型返回的图片顺序；第二视觉模型返回 `correctAnswer` 并触发讲解复修。

批量回归结果：**9 个已生成题图 URL，9/9 返回 HTTP 200，内容类型为 `image/jpeg`。**

## 8. 当前缺陷与风险

| 编号 | 风险 | 严重度 | 当前缓解措施 |
|---|---|---|---|
| R-01 | 小模型可能生成错误或不完整讲解 | 高 | 第二模型与视觉模型复核，冲突进入人工审核 |
| R-02 | 模型输出的反斜杠可能变成 JSON 控制字符 | 高 | 公式异常检测和 MinerU 原题规范化回退 |
| R-03 | 第一批历史持久化题目可能没有 `review` 字段 | 中 | 重新生成对应批次后补齐审校记录 |
| R-04 | 当前真实样本数量过少，不能排名模型 | 高 | 持续扩充脱敏 gold set，并用 Judge 报告批量横评 |
| R-05 | 不同 Provider 的 token 字段并非都可用 | 中 | 报告显式保留 `null`，不以字符数冒充 token；按真实运行补充可用 Provider 数据 |
| R-06 | `needs_review` 仍展示了未经人工修订的讲解 | 高 | 生产版应禁止发布，只允许管理员预览和修订 |
| R-07 | 本地文本模型不是视觉模型 | 中 | 独立使用 Codex 视觉审校；后续加入本地 VLM 对照组 |
| R-08 | 评审模型自身可能没有区分能力，把噪声当质量分 | 高 | 语料带 `factualLabel` 标注，`judgeMetrics.scoreDiscrimination` 逐维度量化；`qwen2.5:3b` 已实测不合格，见第 10 节 |

## 9. 多模型横向评测方案

本轮只验证了当前默认组合，不能据此声称某个模型总体优于其他模型。正式横评建议准备至少 50 道人工校对题，覆盖选择题、填空题、证明题、公式密集题、单图、多图、跨页和低清晰度扫描。

### 9.1 金标准字段

每道题至少维护：

```json
{
  "goldPrompt": "人工确认的完整题干",
  "goldFormulae": ["AB \\parallel DC", "AB=\\sqrt{5}"],
  "goldGivens": ["AB∥DC", "AB=AD"],
  "goldOptions": [],
  "goldImageIds": ["question-21.jpg"],
  "goldVisualFacts": ["AC与BD交于O", "CE⊥AB"],
  "goldLessonFacts": ["待求量为OE"],
  "knownOcrErrors": ["根号错误", "平行符号错误"]
}
```

### 9.2 固定实验条件

- 所有模型使用同一份 MinerU Markdown 和同一组原图。
- 使用相同 JSON Schema、提示词、上下文长度和最大输出长度。
- temperature 固定；每个模型每题至少运行 3 次。
- 保存原始输出，不只保存最终合并结果。
- 评分人员不知道输出来自哪个模型，减少主观偏差。

当前离线工具已经固化了 16 条脱敏讲解样本（其中 6 条带植入错误，见第 10 节）。`judge_cli` 报告使用 `judge-report-v2` 契约，记录
`reportKind`、语料版本、`sampleSetHash`、审核 Provider/Model/Prompt 版本，以及每条样本的
`judgeSucceeded`、评分、耗时、逻辑调用数、Provider 实际尝试数、token（未知时为 `null`）和 Schema
降级信息。聚合字段统一放在 `judgeMetrics`，不命名为 `modelMetrics`，因为它们描述的是审核运行而不是
被评讲解模型的生成质量。报告文件包含唯一 `runId`，多次运行不会覆盖基线。

确定性报告和 Judge 报告由 `python -m evaluation.compare` 分开比较：前者检查结构回归，后者只在语料、
样本哈希和审核配置一致时比较共同成功样本的配对评分；缺失指标不按零计算，评分变化只展示、不自动失败。

### 9.3 指标定义

| 阶段 | 指标 | 定义 |
|---|---|---|
| 结构化 | 题干完整率 | 完整保留全部题干和小问的题目比例 |
| 结构化 | 公式准确率 | 与人工金标准完全等价的公式数 / 公式总数 |
| 结构化 | 条件召回率 | 正确抽取条件数 / 金标准条件总数 |
| 结构化 | 跨题污染率 | 混入相邻题或答案内容的题目比例，越低越好 |
| 文字审校 | 错误修正率 | 正确修复的已知错误数 / 已知错误总数 |
| 文字审校 | 漏检率 | 未发现错误数 / 已知错误总数，越低越好 |
| 文字审校 | 误改率 | 把原本正确内容改错的次数 / 原本正确字段数，越低越好 |
| 视觉审校 | 图片归属 F1 | 对正确题图的 Precision 与 Recall 调和平均 |
| 视觉审校 | 视觉事实准确率 | 正确识别的点、线、数值和关系 / 全部输出事实 |
| 讲解审校 | 冲突检出率 | 被发现的已知讲解冲突 / 已知冲突总数 |
| 运行质量 | Schema 成功率 | 返回可解析且通过 Schema 的响应比例 |
| 运行质量 | 稳定性 | 同题三次运行中关键字段一致的比例 |
| 性能 | P50/P95 耗时 | 模型调用端到端耗时分位数 |
| 成本 | 单题成本 | 本地耗时/内存或云端 token/API 费用 |

审校模型必须优先关注误改率。宁可把低置信度题目标为人工复核，也不能擅自改坏正确题目。

### 9.4 建议综合评分

```text
结构化得分 = 题干完整率×30% + 公式准确率×30%
             + 条件召回率×20% + (1-跨题污染率)×20%

审校得分 = 错误修正率×35% + (1-漏检率)×20%
           + (1-误改率)×35% + Schema成功率×10%

视觉得分 = 图片归属F1×40% + 视觉事实准确率×30%
           + 冲突检出率×30%
```

建议设置硬门槛，而不是只看总分：

- 公式准确率不低于 98%。
- 审校误改率不高于 1%。
- 图片错配率不高于 1%。
- 跨题污染率不高于 0.5%。
- Schema 成功率不低于 99%。
- 任何高风险讲解冲突必须进入人工复核。

## 10. 讲解评审有效性实测（2026-09-05）

本节是一次**独立执行并有结论**的实测，不是计划。与第 9 节的横评方案区别在于：这里评的不是
"哪个模型讲得更好"，而是**"评审模型本身能不能评"**。

### 10.1 起因：一个自相矛盾的读数

`run_judge_agreement` 与 `run_generation_comparison` 各跑出过一次真实结果，两者在 `factual`
维度上互相矛盾：

- 评审一致性里，两个评审模型对同一批固定讲解的 `factual` 打分极差可以到 **3 分**（满分 5）。
- 生成质量对比里，同一个 `factual` 维度对三个候选生成模型**全部打满分**，毫无区分度。

同一维度既极度分歧、又完全没有区分度，不可能同时成立，说明至少有一个读数是无效的。

### 10.2 诊断：语料里没有错误讲解

原 8 条 `EXPLANATION_SAMPLES` 全部是人工手写的引导卡，全部数学正确。**一个只包含正确样本的
语料无法证伪 `factual` 维度**：无论评审模型打什么分，都没有对照可以判断它是评对了还是在猜。
一致性指标在这种语料上尤其有误导性——两个评审可以稳定地打出同一个分，同时一起看不出任何错误。

### 10.3 方法

1. 语料扩到 16 条，每条标注 `factualLabel`：`sound` 10 条、`flawed` 6 条。
2. `flawed` 样本各植入**一处**数学错误，`flawNote` 写明植入内容；语言保持清晰、针对学生卡点，
   只有数学内容是错的。这样 clarity / targeting 就成为对照维度：若它们与 `factual` 一起掉分，
   说明评审只是整体印象变差，并没有定位到数学错误。
3. 标注**不进提示词**（`build_judge_prompt` 只读 `questionContext` 和 `explanation`），由
   `test_evaluation_corpus` 锁定，避免评审照抄答案。
4. 新增 `judgeMetrics.scoreDiscrimination`：`gap = soundMean - flawedMean`，逐维度计算。
   任一类样本无成功评分时返回 `null` 而不是 0——0 是"测到了、没有差异"，`null` 是"没测成"。
5. rubric 保持 `judge-rubric-v1` 不变，先分离"语料问题"与"提示词问题"两个变量。

### 10.4 结果（两次独立运行）

| 评审模型 | 运行 | `factual` sound | `factual` flawed | `factual` gap | `targeting` gap | `clarity` gap |
|---|---|---:|---:|---:|---:|---:|
| Ollama `qwen2.5:7b` | 1 | 5.00 | 3.17 | **+1.83** | +1.77 | +0.63 |
| Ollama `qwen2.5:7b` | 2 | 5.00 | 2.67 | **+2.33** | — | — |
| Ollama `qwen2.5:3b` | 1 | 4.10 | 4.20 | **-0.10** | +0.40 | 0.00 |
| Ollama `qwen2.5:3b` | 2 | 4.33 | 4.17 | **+0.16** | — | — |

`qwen2.5:7b` 逐样本（运行 2）：10 条 sound 全部 5 分，无一例外；6 条 flawed 中——

| 植入的错误 | 打分 | 判定 |
|---|---:|---|
| 编造题干没有的"等腰三角形"条件 | 1 | 抓到 |
| 中位数定义说成"出现次数最多的数" | 1 | 抓到 |
| 勾股定理算出 100 后漏开方，断言斜边为 100 | 1 | 抓到 |
| 不等式两边除以负数不变号 | 4 | 只察觉异常，未判为错误 |
| 幂的乘方误作指数相加，(x³)²=x⁵ | 4 | 只察觉异常，未判为错误 |
| 编造"两边加任一角相等即全等"（SSA） | **5** | **完全漏检** |

### 10.5 结论

1. **原假设不成立。**矛盾读数的原因既不是 rubric 太松、也不是语料不够典型，而是语料里
   **没有错误讲解**可供区分；叠加上其中一个评审模型在该维度上输出的本就是噪声。
2. **`qwen2.5:3b` 不能用作评审模型。**两次独立运行的 `factual` gap 分别为 -0.10 和 +0.16，
   等价于随机。它在运行 2 里给"编造 SSA 全等判定""漏开方""中位数定义错误"三条全部打了 5 分，
   却给两条**正确**讲解打了 2 分。`judge_cli` 的默认评审模型必须保持 `qwen2.5:7b`。
3. **rubric 未作改动。**有能力的评审模型在 `judge-rubric-v1` 下即可区分对错（sound 侧 10/10
   稳定满分）。此时改 rubric 会把"模型能力不足"错记成"提示词问题"。
4. **失败模式集中在"听起来合理的错误通则"**，而不是算错。`qwen2.5:7b` 对具体的算错和编造条件
   反应强烈（打 1 分），却完整认可了一条不存在的全等判定定理。这正是辅导产品最危险的一类错误：
   学生会把它当成可复用的规则。
5. **维度之间不独立。**`qwen2.5:7b` 的 `targeting` gap（+1.77）几乎与 `factual` gap（+1.83）
   相当，而植入的错误只在数学内容上。这是光环效应：一旦判定内容有误，其他维度跟着下调。
   `clarity` gap 只有 +0.63，说明是部分光环而非全面塌陷。分维度打分不能当作彼此独立的证据。

### 10.6 尚未做、以及为什么

- **没有针对 SSA 漏检收紧 rubric。**这目前只有 1 条样本支撑，照着它改 rubric 属于对 N=1 过拟合。
  正确做法是先补充同类样本（编造定理、错误通则、过度推广的结论），确认这是稳定的失败模式，再谈改。
- **没有把区分度接入生成质量对比。**`factualLabel` 标注的是手写讲解原文对不对，而生成对比评的是
  模型现场生成的新文本，标注对它不成立。只有评审静态语料的 `judge_cli.run_all` 那条路径能算区分度。
- **N=16 仍不构成统计显著性。**报告里的 `statisticalNote` 依旧成立，本节结论按方向性证据使用；
  其中 `qwen2.5:3b` 的结论相对可靠，因为它在两次运行中都落在"无区分"上，且方向相反。

## 11. 验收结论

### 已通过

- PDF 批次处理、题目切换和 SQLAlchemy 存储兼容自动化测试通过。
- 本机 SQLite 的 6 个上传任务、68 道题已迁移到 PostgreSQL，JSONB 类型、外键和 API 教材库读取验证通过。

- 前端类型检查和生产构建通过。
- 第二文本模型和视觉模型均在真实教材样例上完成调用。
- 视觉模型正确匹配题图并输出可验证的图形事实。
- 错误讲解被标记为 `needs_review`，审校门禁有效。

### 未通过或尚未完成

- 当前样例讲解本身仍存在逻辑错误，不能直接发布给学生。
- 尚未建立不少于 50 道题的人工金标准数据集。
- 尚未完成不同生成模型、审校模型和视觉模型的统计性横向评测。
- 当前工具已能记录审核运行耗时、Provider 请求次数和可用 token，但尚未完成跨模型的统计性横评。

离线评测工具；在受控公网测试前，仍应优先扩充金标准评测数据集并完成批量横评。自动恢复不能替代模型
效果评测，整套内容无合格题时必须继续拒绝发布。
