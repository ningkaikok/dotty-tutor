# 整本教材自动续做

整本自动续做是教师明确选择的课件制作范围。进入整本模式后，服务端按原 PDF 物理页码建立持久批次，并复用现有教材来源准备、规划、课件生成、自动检查、修复和发布流程。普通页段制作和试卷原题流程保持原有入口。

## 范围与上限

- 最多处理 1000 个原 PDF 物理页。
- 每批最多 30 个物理页，最多 34 批（`ceil(1000 / 30)`）；773 页教材覆盖原页 1–773 并分成 26 批。目录标题只会在不突破该批次数上限时作为批次边界。
- 每批最多生成 45 张课件页。超过预算的规划会进入异常状态，不会静默截断。
- 教师可以在等待或制作时暂停，再从未完成批次继续。已经发布的课时、教师编辑和来源版本均保留。
- 非教学页只有在规划为每个原页提供原因并通过原页检查后，才计入完成进度。OCR 未识别的原页只在整本模式下保留物理页占位；原 PDF 文字层只要有文字就不能判为空白，扫描页使用原分辨率检查连片墨迹，证据不足时保留原页供人工检查。普通页段来源规则不放宽。

## 教师界面

在“教材互动课件”中选择已识别教材，选择“整本自动续做”并提交。界面显示页数上限、分批上限和每批课件页上限；开始后显示各批物理页范围、当前阶段、已完成页数、跳过页原因及需要处理的异常。

整本状态从服务端持久化任务读取，页面刷新后会恢复最新进度。`waiting_for_source` 表示原 PDF 等待恢复，此状态暂不能暂停；`paused` 状态可继续。已发布批次提供直达课件入口，不必返回教材库查找；失败批次不会重做已发布批次。

## HTTP 接口

以下接口只允许教师调用。启动和控制请求都需要显式的教材意图；重复启动同一来源和设置会复用原任务。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/uploads/{upload_id}/courseware/whole-book` | 明确开始整本制作。请求包含 `mode: "whole_book"`、`subject` 和可选的标题/来源署名/分发范围。 |
| `GET /api/uploads/{upload_id}/courseware/whole-book` | 读取该教材最近一次整本任务。 |
| `GET /api/courseware/whole-book-runs/{run_id}` | 读取运行状态与批次进度。 |
| `POST /api/courseware/whole-book-runs/{run_id}/pause` | 请求暂停，JSON 请求体含唯一 `commandId`。 |
| `POST /api/courseware/whole-book-runs/{run_id}/resume` | 从未完成批次继续，JSON 请求体含唯一 `commandId`。 |

状态 GET 只读取任务、教材记录、课件记录和文件清单，不创建任务、不调用模型，也不恢复/下载整本 PDF。若本机缓存缺少 PDF，状态通过数据库中的文件清单和 OCR 文本指纹判断来源是否变化；真正需要原页内容时由 Worker 恢复原件。

暂停/继续命令按 `run_id + action + commandId` 幂等。同一命令在响应丢失后重试会返回当前进度，不再追加续做任务；不同命令仍按当前运行状态校验。

## Worker 接线

`WholeBookService` 接收现有 `store`、`jobs`、`material_courses` 和 `courseware` 服务。`build_whole_book_registry(service)` 注册整本控制任务；`add_whole_book_completion_hooks(registry, service)` 包装已有章节/课件任务注册表，在来源、规划、页面生成和自动检查任务结束后续接整本队列。由应用装配处将两份被包装的注册表与整本注册表合并，并通过 `build_whole_book_router(service)` 注册教师 HTTP 接口。

整本服务本身不实现新的 OCR、生成或审核运行时，不会替代现有课件 Worker。

## 验收

当前验收使用真实 PostgreSQL 隔离测试库，模型只在外部模型边界使用确定性替身。覆盖多批发布、暂停/继续、来源变化、冷缓存只读状态、缺失 OCR 页占位、教师接口、并发幂等、手工编辑保护和试卷拒绝。浏览器流程覆盖整本启动、暂停和继续。
